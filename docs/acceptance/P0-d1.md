### 4.1 证据链：commit → run → job → artifact → 文件

### 4.2 启动路径确实是 OVMF + GRUB + 磁盘，而不是 `-kernel`

- `boot-check.sh` 的 UEFI 分支（`tools/boot-check.sh:1449-1469`）使用：


  **没有** `-kernel`/`-initrd`/`-append`；kernel 模式才有 `-kernel`（`tools/boot-check.sh:1471-1483`）。
- job log 打印 `firmware: /usr/share/OVMF/OVMF_CODE_4M.fd`、`launching qemu-system-x86_64 (uefi/OVMF, ...)`；boot.log 有 OVMF `BdsDxe`、`GNU GRUB 2.14` 菜单与 3 秒倒计时、`EFI stub`、`EFI v2.7`。如果 CI 用 `-kernel` 直启，不会有这些。

### 4.3 `sysemble-boot-evidence.service` 是 systemd 真实执行，不是预埋字符串

- 构建侧：`build.sh:337-350` 生成 unit 文本并追加到 `--customize-hook`；build.log 第 7 行记录安装/启用，第 9/35 行记录 hook 全文；unit 文本含 `After=graphical.target`、`WantedBy=graphical.target`、`graphical.target.wants` 符号链接和 `systemctl enable`。

## 6. 风险与未验证项（不阻塞本轮 PASS）

### R1 — `boot.xorg` 的 Xorg 证据来自 marker，不是 Xorg 自身日志（中）

- boot.log 中 `X.Org X Server` 原文 **0 处**；`Xorg` **仅 1 处**，就是 evidence unit 写的 `SYMBLE: Xorg ready`。
- 该 marker 有真实 pgrep 门槛（`pgrep -x Xorg` 成功才写），并且 unit 的 systemd Starting/Finished 行都在，所以“Xorg 进程存在”是被证实的；但**不能**从 marker 推出“Xorg 初始化成功、greeter 可用、画面已渲染”。
- LightDM 把 Xorg 的 stdout 重定向到 `/var/log/lightdm/x-0.log`；rootfs 未上传，无法读取该日志；也没有截图/framebuffer 检查。
- **影响**：D5 的“X.Org”严格说只是 `Xorg` marker，不是 X.Org 自身日志；结论“DM/X 起来”成立，但“greeter UI 可用”未被独立证明。
- **建议**：evidence 增加 Xorg 自身日志（或 `journalctl -u lightdm` / `x-0.log` 摘要）、`pgrep -a Xorg`、greeter 进程；或加 `-display none` 下的 framebuffer 截图/`xrandr` 检查。

### R2 — marker 竞态：unit 在 `graphical.target` 后立即 pgrep，且 `true` 掩盖失败（中）

- unit 是 `After=graphical.target` + `WantedBy=graphical.target`，在 target 刚到达时执行；LightDM 启动 Xorg 是异步的。本次 `lightdm Started` 16.913798 → unit Starting 16.940895 → Finished 17.153240，unit 的执行窗口约 **212 ms**；Xorg 在这个窗口内已就绪，两条 marker 都出现。若 Xorg 晚于该窗口才就绪，marker 就会缺失。
- `ExecStart` 末尾是 `true`，所以即使 pgrep 失败，unit 仍以 0 退出，systemd 仍打印 `Finished`；此时 boot-check 只会在 600s 后 timeout 失败（**不会假通过**，但会变成 flaky 失败）。
- 只有一次绿，无法估计 flake 率。
- **建议**：unit 内改成带超时的轮询（例如最多 10s 每秒 pgrep 一次），全部找到才写 marker；或 boot-check 对 marker 单独重试；CI 增加 repeat/retry 统计。

### R3 — 只证明 DM/X 起来，没有登录用户会话（范围说明）

- `login:` 是 serial getty 的 `debian-xfce login:`（boot.log 第 804 行），不是 LightDM greeter 的登录；没有输入用户名/密码，没有启动 XFCE session（boot.log 无 `xfce4-session`/`xfwm`/`xfdesktop`）。
- `desktop.session=xfce` 是从 `plan.packages` 的 `xfce4` 推断的 artifact 字段，不代表 session 真实运行。
- **影响**：本切片只到“DM/X 起来 + serial login 提示”；不能外推为“XFCE 桌面可用/可登录”。
- **建议**：P0-d3 增加 LightDM autologin 或 serial 登录后 `xfce4-session`/`xfwm4` 进程与 `xrandr`/截图断言。

### R4 — 断言模式偏宽，`boot.graphical` 可被 cmdline 满足（低-中）

- `boot.graphical` 匹配 `graphical.target`；该字符串在 kernel cmdline（boot.log 第 9/145 行）就出现，即使 target 没到达也会 pass。本次第 791 行确实有 `Reached target graphical.target - Graphical Interface`，所以实际结论成立；但断言本身不独立。
- `boot.display_manager`/`boot.xorg` 的 token 也出现在 marker 文本中（marker 是刻意设计，见 R1）。
- **建议**：`boot.graphical` 改为匹配 `Reached target graphical.target`（注意 ANSI 清理）或 `systemd[1]: Reached target graphical.target`；marker 输出使用不含断言 token 的独立协议（或 evidence 额外记录 pgrep 输出）。

### R5 — LightDM 缺 `accountsservice`，用户列表报错（低）

- boot.log 第 792 行：`lightdm[638]: Error getting user list from org.freedesktop.Accounts: ... ServiceUnknown`。
- 按 [Debian trixie 的 lightdm 依赖](https://packages.debian.org/trixie/lightdm)，`accountsservice` 是 Suggests；`--variant=minbase` + 不装 Recommends/Suggests 时不会安装。不影响 LightDM/Xorg 启动，但 greeter 的用户列表可能为空/不完整。
- **建议**：P0-d3 显式把 `accountsservice` 加入桌面运行时包，或确认 greeter 在无 Accounts 时的可用性。

### R6 — 只验 XFCE/LightDM；KDE/GNOME/SDDM/GDM 未验（范围）

- 本轮 artifact 是 `session=xfce`、`display_manager=lightdm`；没有 KDE/Plasma、GNOME/GDM、SDDM 的真实构建/启动。
- `examples/debian-kde-dev.yaml` 只做了 plan/validate 级别测试；KDE 在 `-vga virtio` + TCG 下渲染更重，workplan 已明确留到后续。
- **建议**：P0-d 增加 KDE/SDDM 的真实 desktop-smoke（可与 XFCE 并行/手动触发），或明确“KDE 不在本切片验收范围”。

### R7 — 无 ISO/安装器（范围）

- artifact 只有 `disk.img` + `disk.qcow2`；build.log 没有 xorriso/squashfs/Calamares；`builders/debian/README.md` 的 “Not implemented in P0-d1” 明确列出 ISO/安装器/持久化/secure boot。
- 本切片只证明“构建出的磁盘镜像能被 OVMF/GRUB 启动到 graphical target”，不证明“可安装的发行版 ISO”。
- **建议**：P0-d2/P0-d3 单独验收 ISO/安装器/首启。

### R8 — TCG + `-vga virtio`，单次绿，性能/稳定性未评估（低-中）

- job log 的 QEMU 参数是 `-vga virtio`、`-m 2048`；boot-check 没有 `-enable-kvm`/`-accel kvm`，GitHub-hosted runner 通常无嵌套虚拟化，实际为 TCG（job log 未直接打印 accelerator，属代码+README推断）。
- 本次 guest 启动 17.164s、boot-check 24s，属正常；但 Xorg/llvmpipe 在 TCG 下可能慢或偶发失败；只有一次样本。
- **建议**：evidence 记录 `qemu --version`、accelerator、argv；CI 增加重复运行或 flake 统计；必要时按 workplan 回退 `-vga std`/`nomodeset` 对照。

### R9 — `rw` 启动改写镜像，artifact 的 image sha 启动后过期（低）

- boot.log 第 490 行显示 root 以 `r/w` 挂载；systemd 会写 machine-id/random-seed/journal 等。artifact 的 `disk.img.sha256` 是构建时摘要，QEMU 启动后 raw 镜像已被写脏。
- **影响**：不能用 boot 后的 `disk.img` 去核对 artifact 的 sha256；这是 P0-c 遗留风险，不是 P0-d1 回归。
- **建议**：冒烟用 `-snapshot`/overlay；boot 前校验摘要；发布物不要用 boot 后的 raw。

### R10 — 边界说明：`tests/acceptance/run.sh` 两行 allowlist（流程/低）

- commit `5d49c5f` 的 12 个文件中，10 个在 W1–W3 产出目录，1 个是主线程的规划文档，另有 `tests/acceptance/run.sh` 不在 P0-d1 W1–W4 表内。
- diff 只有 2 行：把 `examples/debian-xfce.yaml` 加入 A10 的 example 允许列表和 frozen-dir 排除；没有删除任何检查、没有放宽 `spec/` 或其他 examples，也没有产品代码/CI 行为变化。
- **结论**：这是新增 example 的必要 harness 更新，不是功能越界；但严格按“变更只在允许目录”应让主线程确认/记录。
- 另外，CI 只跑 schema/cargo/boot-smoke/desktop-smoke，不跑 `artifact_test.sh`/`build_exec_test.sh`/`boot-check-test.sh`；本轮本地全跑通过，但 CI 不强制（P0-c R10 仍在）。

### R11 — 其他非阻塞观察（信息）

- `systemd.journald.forward_to_console=1` 是 P0-d1 新增的 cmdline 参数，不在 workplan §2 的示例 cmdline 中；它是为了让 LightDM/Xorg 日志落到串口，属有意扩展，D3 只要求 cmdline 含 `graphical.target`。
