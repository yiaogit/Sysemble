### 6.2 体积数字复现与设计必须修正项

本机独立复算：

| 项 | 实测 |
|---|---|
| `disk.img` 逻辑/实际 | 6,442,450,944 B / **553,435,136 B**（540,464 KiB） |
| `disk.img.zst` | **202,579,256 B = 193.19 MiB**；`zstd -d` 14.17s，解压 sha256 `bbde42f8…124a021` **等于** `disk.img` |
| 重算 `zstd -19 -T0` | **202,445,763 B = 193.07 MiB**，23.78s；**“193 MiB”可复现**（与 ADR 202,579,256 B 相差约 0.06%） |
| `vmlinuz` / `initrd.img` | 37,797,824 / 36,024,136 B；压缩资源合计 **276,401,216 B = 263.6 MiB** |
| app（估算 30–40 MiB） | **约 294–304 MiB**；ADR 写 280–300 MiB，上限略保守 |
| 安装后（disk 实际 + kernel + initrd） | **627,257,096 B = 598.2 MiB**；ADR 写 ~560 MiB，偏低约 38 MiB |
| 单次构建实测 | `vm-disk.img` 1,547,888 KiB（≈1.48 GiB）+ tarball 246,337,666 B（≈235 MiB），峰值约 **1.71 GiB**；ADR 写 0.8–1.5 GiB + 0.25 GiB，略低 |
| 非 APFS 最坏情况 | 6.0 GiB 全量 disk + 1.71 GiB 构建 ≈ **7.7 GiB**；ADR 的“8 GiB 以上”没有余量，且 8 GiB 预检本身会被 6.44 GB 逻辑盘吃掉 |

**必须修正项（E5 实施前）：**

1. **克隆清理与 `--keep-disk` 的表述与实现不符**。ADR §2.4/§7 写“构建结束默认删除克隆”“`--keep-disk` 仅调试”；实际 helper 既不删除 `<out>/vm-disk.img`，也没有 `--keep-disk` 参数（代码里只有 `--no-clone`；E2E 的 out 在测试删除前明确含 6 GiB `vm-disk.img`）。需二选一：在 E5 实现“停止 VM 后删除 clone / 提供 `--keep-disk`”，或修正 ADR 为“clone 保留在 out，下一次构建替换，清理由 UI/用户完成”，并把磁盘预算改为含保留 clone。
2. **安装目录内容与原子性未定义完整**。`engine.rs` 要求镜像目录同时有 `sysemble-vm.json`、`vmlinuz`、`initrd.img`、`disk.img`；ADR §5 只详细描述 `disk.img` 的落盘。必须明确把清单/kernel/initrd 一并放进 `<version>/`（复制或受控链接），并采用 **`<version>.tmp` 整目录写入 → fsync → rename**，避免 probe 选中半安装版本。稀疏解压还应在最后 `set_len(logical_size)`，否则最后若干块为全零时文件长度可能短于 6 GiB；启动时清理 stale `.tmp`。
3. **版本选择/兼容语义冲突**。workplan §6.5 要求“镜像版本与应用版本绑定”，ADR §2.6 却写“app 与镜像版本解耦”，同时计划 `min_app_version`；当前 `newest_installed_vm_image` 只按最高有效版本选择，未读取 `installed.json` 或 `min_app_version`。需明确：旧 app 是否允许启动更新镜像；`min_app_version` 不满足时是拒绝、降级还是提示；GC 只删“低于保留窗口且无构建引用”的目录。
4. **磁盘预检数字不足**。按实测，安装后约 598 MiB、一次构建约 1.71 GiB；APFS 稀疏盘可把 6 GiB 逻辑压到 528 MiB 实际，但**非 APFS/普通写入**需要 6.0 GiB 全量，8 GiB 总预检不够。应改为：APFS 预检 ≥8 GiB，非 APFS 预检 ≥10 GiB；L2 的 8–9 GiB 安装盘另列预算（ADR §8 已给 L2 数字，但未并入 §4 预检）。
5. **兼容矩阵与失败模式补齐**。§7 表需增加 Windows/WSL2（后续/不支持）、Linux（native/容器）两行；失败模式表需补：helper 版本/ABI 不兼容、首启安装中断后的恢复、签名通过 `validate()` 但 `VZVirtualMachine.start()` 被 MDM/策略拒绝、压缩包截断、clone 清理失败；每项给用户提示与恢复动作。
6. **签名范围需明确到 Tauri 嵌套代码**。ADR 只写 helper + app 两级；实际 `.app` 还含 Tauri 框架、sidecar、dylib。必须逐个以同一 Developer ID + hardened runtime 签名（或由 Tauri 以 Developer ID 构建并验证），再封 app；不能依赖 `--deep` 签名；补 `LSMinimumSystemVersion=13` 与 `codesign --verify --deep --strict`/`spctl`/公证检查清单。

**建议但非阻塞：** ADR §7 “app 内串行化 VM 构建”目前只由 UI 的 `buildRunning` 保证（[app.js](../../apps/desktop/ui/app.js#L68)），后端 `BuildManager::start_build` 未拒绝并发；E5 若开放多窗口/IPC，应加后端互斥或把表述改为“UI 串行化”。另建议把 README 中文结尾的“原生 VZ/WSL2 helper 在 P1-e3”改为 E4 现状（VZ 已接入、WSL2 尚未实现）。

## 8. 风险与限制

1. **GUI 未自动化**：没有 Tauri WebView/浏览器点击、截图或 IPC 端到端测试；UI 的 `Engine: vm · arm64`、Build 门控、tooltip、取消按钮仅做静态源码核对。真正的 App 级 E2E 通过 `BuildManager` 库层完成（[real_vm.rs](../../apps/desktop/src-tauri/tests/real_vm.rs#L240)），不是 GUI 点击。
2. **arm64-only**：VM 镜像和 guest 产物都是 arm64；helper 拒绝非 arm64 host；x86_64 目标仍走 Docker/podman 容器后端（README 已写明）。
3. **x86_64 一体化差距**：ADR L1 的“零 Docker”只覆盖 arm64；L2 的 engine-in-VM/Rosetta 仍是设计+待 spike，未在本切片验证。Windows/WSL2 也未实现。
4. **macOS 13/14 未实测**：本机 26.6.2，CI 15.8.2 且不能启 VZ；`supported="unknown"` 仅单测覆盖，真实 13/14 的 `run` 仍可能被 `validate()`/策略拒绝。ad-hoc 签名未公证，分发给他人会被 Gatekeeper 拦截。
5. **前置 P1-e3 V10 用户设备半边仍 BLOCKED**：需要在第二台 Apple Silicon Mac 上执行 P1-e3 §7.1 清单；本切片无法替代，也不把它写成 PASS。
6. **CI 不能启动 VZ**：CI 只证明编译/签名/probe；真实 VM 只在本次本机运行。CI 的 `Desktop app (check)` 在本机 macOS 上才会注册 `real_vm` 的 ignored 测试（CI Linux 为 0 测试）。
7. **非位级可复现**：两次 E2E 的 tarball sha256 不同（mmdebstrap 时间戳）；每次内部一致，但跨构建不可比。不要把“两次 sha 不同”误判为产品失败。
8. **封装尚未实现且 ADR 有待修正**：没有 `.app`、Developer ID、公证、首启安装器；clone 保留、安装目录内容、`min_app_version`、非 APFS 预检等见 §6.2。设计 PASS 不等于 E5 可以直接照抄。
9. **磁盘/临时空间**：每次构建在 out 保留 6 GiB 逻辑（实测 1.48 GiB 实际）的 `vm-disk.img`；重复 out 会替换，但不同 out 可能累积。用户清理 UI/说明尚未实现。
10. **边界语义**：VM 镜像缺失 + 容器 daemon 可达但容器镜像也缺失时返回 `container/available=false` 而非 `vm/available=false`；不误报可用，但建议主线程统一口径。

## 9. 结论

**P1-e4 在本机真实 VM 与 CI 证据下 W1–W9 全部 PASS，FAIL 0；W8 的封装设计覆盖通过但必须在 E5 前修正 6 项（clone 清理、安装目录/原子落盘、版本兼容、磁盘预检、兼容/失败矩阵、签名范围）。封装与 x86_64 一体化尚未实现，报告未将其写成已实现；前置 P1-e3 V10 用户设备半边仍 BLOCKED。**
