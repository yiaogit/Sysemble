# ADR-0002: 基础谱系 L0–L4，由问询推荐，L4 需二次确认

- 状态：Accepted
- 日期：2026-11-23

## 背景

用户需求从"一个 200MB 的服务器"到"我想从零编译一个系统"跨度极大。若只支持一种基础，会丢失一半场景；若让用户自选，多数人会选错（例如在 Alpine 上装 glibc 桌面）。

## 决策

定义五级基础谱系：

| 级别 | 基础 | 体积 | 时长 |
|---|---|---|---|
| L0 | Alpine / Buildroot | < 300 MB | 5–15 min |
| L1 | Debian/Ubuntu minbase | 300–600 MB | 10–25 min |
| L2 | L1 + 桌面 + 软件 | 2–4 GB | 20–45 min |
| L3 | 官方 ISO remaster | 3–6 GB | 15–30 min |
| L4 | 字面 LFS | 3–8 GB | 8–20 h |

由**结构化问询**（用途、软件清单、硬件、维护意愿、时间/磁盘预算、技能、合规）推荐级别，并展示理由与代价。

L4 必须二次确认，UI 红标，明确"8–20 小时、可能失败、不适合日常使用"。

## 后果

正面：
- 覆盖从服务器到教学的完整谱系。
- 多数用户被引导到 L2/L3，成功率最高。
- L4 保留为实验室能力，不污染主路径。

负面：
- 五套构建策略意味着五套适配器与测试矩阵。
- L0 的 musl 兼容性与 L4 的失败率会带来支持负担。

## 备选方案

1. **只做 L1–L2**：放弃服务器与教学场景。否决。
2. **只做 L3 remaster**：改动受限，无法表达"从零"。否决。
3. **让用户直接选 base**：把选择成本推给用户，违背"辅助"定位。否决。

## 约束

- P0 只实现 L2（Debian 桌面）。
- 每级都必须有"证明边界"文案，说明保证什么、不保证什么。
